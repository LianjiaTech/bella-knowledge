## 目标

- 扩展现有 `POST /v1/files/move`，让 `file_id` 同时接受普通文件和目录；请求字段、响应结构及同空间限制保持不变。
- 目录移动后完整保留源目录的内部子树，只替换其旧外部祖先链，并让目录、子目录和文件的直属父级、祖先链、路径查询及 `root_depth` 与新位置一致。
- 在执行任何闭包关系写入前拒绝自移动和移动到任一后代目录，避免产生循环；继续拒绝目标非目录、跨空间、当前父目录和目标目录同名冲突。
- 复用同一套子树迁移实现处理叶子文件，保持现有文件移动行为和位置变更事件兼容；闭包关系更新与位置事件写入处于同一事务，任一步失败均整体回滚。

## 非目标

- 不新增管理端拖拽、剪切粘贴、目录选择等交互。
- 不支持跨空间或跨分片移动。
- 不修改 `FileMoveOps`、接口 URL、请求字段和 `OpenAIFile` 返回结构。
- 不迁移存储对象内容；目录层级仍以 `file_closure` 为准，文件对象的存储 `path` 不因逻辑目录移动而重写。

## 当前上下文

- `api/src/main/java/com/ke/bella/files/api/FileController.java` 的 `move` 已完成目标目录、上下文空间、源对象、当前父目录和同名冲突校验，但通过 `file.getIsDir() == 0` 明确排除了目录。
- `api/src/main/java/com/ke/bella/files/service/FileService.java` 的 `moveFile` 已使用 `@Transactional(rollbackFor = Exception.class)`，但当前先调用 `deleteFileClosure` 删除源节点作为祖先或后代的所有关系，再调用 `addFileClosures` 只恢复源节点；该方式只适用于没有后代的叶子文件。
- `api/src/main/java/com/ke/bella/files/db/repo/FileRepo.java` 的闭包表关系以 `ancestor_id`、`descendant_id`、`depth` 表示；每个节点有一条 `depth = 0` 的自关系，并在该自关系上保存从空间根开始的 `root_depth`。普通祖先关系的 `root_depth` 为 `-1`。
- 用户文件分片键由空间编码哈希写入文件 ID；同空间校验也保证本次移动涉及的源子树、目标祖先链和闭包更新落在同一个逻辑分表及本地事务中。
- `api/src/test/java/com/ke/bella/files/api/FileControllerMoveTest.java` 已覆盖文件移动成功和主要参数错误，但尚无真实闭包关系的子树移动回归测试。

## 方案

### 1. 放开接口类型并收拢移动前置校验

- 修改 `FileController.move`，删除“源对象必须为文件”的限制，保留源对象存在、目标存在且为目录、操作空间与源/目标空间一致等校验。
- 继续使用目标目录、源名称组成的 `FileUniquenessLock`，并在获得锁后重新检查当前直属父目录和目标目录同名对象，避免锁等待期间目录状态变化后仍按过期结果执行。
- 对目录源增加环路校验：目标 ID 等于源 ID，或闭包表中存在 `源 -> 目标` 的祖先关系时，返回明确的参数错误。环路判断放入服务事务内，并由控制器透传 `IllegalArgumentException`，确保校验依据与后续写入处于同一数据库状态窗口。
- 普通文件继续走相同入口；文件没有非自身后代，因此新的子树算法自然退化为当前叶子移动语义。

### 2. 以子树为单位替换闭包关系

- 在 `FileRepo` 新增单一职责的子树迁移方法，由 `FileService.moveFile` 调用，替代 `deleteFileClosure + addFileClosures` 组合；原新增文件时使用的 `addFileClosures` 保持不变。
- 在写入前读取并锁定以下闭包快照：
  - 源节点到所有子树节点的关系，得到每个后代相对源的 `depth`；该集合包含源自身。
  - 目标目录的完整祖先链，包含目标自身，并取得目标自关系的 `root_depth`。
  - 源节点的旧祖先链，用于识别需要删除的外部祖先关系。
- 在快照阶段检查目标是否已位于源子树中；命中源自身或任一后代时立即失败，不执行删除或插入。
- 仅删除“旧外部祖先 -> 源子树任一节点”的跨边关系，保留下列数据：
  - 子树内节点之间的所有祖先/后代关系。
  - 每个子树节点的 `depth = 0` 自关系。
- 批量插入“目标祖先链 -> 源子树节点”的新跨边，深度按 `目标祖先到目标的 depth + 1 + 源到子树节点的 depth` 计算；插入记录继续使用当前空间编码及审计字段，普通关系的 `root_depth` 保持 `-1`。
- 批量更新子树各节点自关系的 `root_depth`，新值为 `目标 root_depth + 1 + 源到该节点的 depth`，从而同步根目录筛选、分页和层级信息。
- 对删除、插入和更新数量做一致性断言；快照缺失、批处理数量异常或唯一键冲突均抛出异常，由 `FileService.moveFile` 的事务整体回滚。

### 3. 保持位置变更后的既有行为

- 闭包关系迁移成功后，继续调用 `updateFile(..., false, Scope.LOCATION)`，保持现有移动操作的位置变更广播、更新时间和返回读取逻辑。
- `getFile(fileId)` 返回源节点；调用方可继续通过现有列表、分页、路径和祖先 ID 接口读取新层级，无需增加新的响应字段。
- 错误响应沿用现有异常映射：资源不存在返回 not found；类型、空间、同父目录、重名和环路等业务校验返回 bad request；未预期数据库错误返回统一移动失败。

### 4. 自动化测试

- 扩展 `FileControllerMoveTest`：增加目录源成功用例，确认目录不再被类型校验拒绝；保留现有文件成功、目标非目录、跨空间、当前父目录、重名及异常映射用例，必要时调整校验发生在锁内后的 mock 顺序。
- 为 `FileService`/`FileRepo` 的闭包迁移增加数据库级测试，构造“旧父目录 / 待移动目录 / 子目录 / 文件 / 新父目录”的多层树，执行目录移动后断言：
  - 源目录直属父级切换为新父目录，旧外部祖先不再关联源子树。
  - 源目录与子目录、文件之间的内部关系和相对 `depth` 不变。
  - 新目标的全部祖先均可访问源子树，新增关系 `depth` 正确。
  - 所有子树节点自关系的 `root_depth` 按新位置整体偏移。
  - `getPathFiles`、`getFileAncestorIds`、直属子项列表或分页查询返回新路径和完整子项。
- 增加非法环路测试：分别覆盖移动到自身、直接子目录和更深后代，断言操作失败且闭包表快照完全未变。
- 增加事务回滚测试：在删除外部关系后模拟插入或根深度更新失败，断言旧祖先关系、内部子树关系和所有 `root_depth` 均恢复，且不产生位置变更结果。
- 继续运行现有叶子文件移动测试，并补充同名冲突、当前父目录、目标非目录和跨空间回归，证明新算法对普通文件兼容。

## 风险与边界

- 子树移动的插入量为“目标祖先数 × 子树节点数”，大目录移动会比叶子文件产生更多闭包写入；实现使用批量删除、批量插入和批量更新，避免逐节点往返数据库，并保持单事务完成。
- 并发移动若涉及同一源子树或目标祖先链，可能产生过期闭包快照；读取关键关系时使用数据库行锁，并在事务内执行环路校验和数量断言，避免交叉移动形成部分关系或循环。
- `file_closure` 的唯一键是 `(ancestor_id, descendant_id)`；方案在插入新关系前只删除旧外部关系并预先拒绝环路，若仍出现重复记录则视为数据状态异常并回滚，不使用忽略冲突掩盖问题。
- 本次依赖“同空间即同用户文件分片”的现有 ID/分片约束；控制器必须在进入闭包迁移前完成源、目标和操作上下文三方空间一致性校验。

## 验证

1. 运行目录移动相关测试：`cd api && mvn -Dtest=FileControllerMoveTest,<新增闭包迁移测试类> test`。
2. 运行 API 模块完整测试：`cd api && mvn test`。
3. 运行代码风格检查：`cd api && mvn checkstyle:check`。
4. 用数据库级断言核对移动前后 `file_closure`：内部关系行数与相对深度不变，旧外部关系清零，新外部关系数量等于“目标祖先数 × 子树节点数”，每个子树节点仅有一条自关系且 `root_depth` 正确。
5. 通过现有接口做行为验收：目录移动请求返回成功；按新父目录列出子项可看到源目录；路径和祖先 ID 查询反映新祖先链；源目录下多层文件和子目录仍可访问；文件移动请求和返回保持原样。
6. 对自身、后代、目标非目录、跨空间、当前父目录和同名目标分别发起请求，确认全部在写入前失败；通过事务故障测试确认失败后闭包关系和位置状态无部分更新。
